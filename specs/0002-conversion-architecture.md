# 架构约束与设计理由

这里只保留跨模块职责和不能从验收结果解释的取舍。行为从 [场景入口](../tests/common/README.md) 阅读，当前批次、执行交接、未交付的产品要求与迁移顺序在统一 [TODO](../TODO.md) 维护，尚待确认的选型与实验在其[技术验证分区](../TODO.md#technical-validation)维护；以下边界不表示迁移已完成。

## 唯一转换路径

```text
Web / CLI / 批处理
        ↓
应用服务：能力选择、任务与发布
        ↓
格式 Reader → 共享规范化 → BookRevision → ExportPlan
                                         ↙       ↘
                                Markdown Writer  HTML Writer → PDF 渲染
```

- 同一格式只有一个正式 Reader，同一输出只有一个 Writer；入口只处理交互与参数，Reader 解释来源，Writer 消费正文与导出计划。PDF 从 HTML 打印结果生成，避免各输出重新解释来源。路由与执行见 [能力表](../src/application/capabilities.py)、[转换用例](../src/application/convert.py)。
- OCR、HTTP、SQLite 和文件系统放在 adapter 边界；配置由应用入口注入，核心不依赖 Web 配置。正式业务归入 `src/`，同步、异步入口及薄脚本复用同一业务实现。
- 替代实现按 TODO 完成切换，不保留同格式双引擎或运行时回退；旧实现只通过隔离 Git 版本作对照。仅剩 Markdown 的资料也不能借迁移恢复旧引擎，其支持范围由 TODO 决定。

## 一份正文与分离的身份

[BookRevision](../src/domain/book.py) 是唯一正式正文，各输出是派生视图，不分别编辑。选用可序列化 HTML 片段，是为了保留表格跨度、脚注、资源与必要样式，避免先转 Markdown 再回转的提前损失；样本依据见 [转换依据](evidence.md#实现取舍)。上游只有 Markdown 时使用 [共享导入](../src/content/markdown.py)，它不能恢复上游已丢信息，也不等于新增独立 `.md` 输入能力。设计目标优先保留内容、结构与阅读顺序，不追求原版面像素复刻。

正文片段的直接归属唯一；章节节点、导航项、来源定位与输出文件分别建模，因为一份正文可以被多次导航，一章也可跨多个源文件。节点身份不依赖标题和文件名，输出格式不参与正文身份；来源、解释选项与 pipeline 版本决定修订适用性。字段以领域模型为准，复用和版本行为由 TODO 的 UC-08 承接。

终态任务换输出由原任务已发布的导出选择正文修订，并在新任务中持久绑定；来源索引不能充当“最新正文”指针。读取以数据库身份及快照 SHA 为信任根，再恢复并校验完整模型、结构与内容归属、资源路径及字节身份。schema-2 不依赖原件在线，坏正文不是缓存未命中；schema-1 缺少完整正文只能显式从保留原件重建。主动提交仍解释来源，重导出保持所选修订的 pipeline 与诊断，不隐式升级解释结果。对应读取、迁移与发布均复用现有应用流程，不维护第二套 Writer。

图片每次出现的源位置保存在共同正文的 `img[data-source-location]`，经过各 Writer 保留到对应内容位置；DOM 使用改写前的文档地址与从 body 开始的同名元素序号路径，DOCX 使用包内 OOXML 路径及 drawing / pict 的段落、运行和容器序号。定位随出现位置持久化，资源仍按内容复用。标题建树与定位解释变更由各 Reader pipeline 区分（HTML / URL / DOCX v2、EPUB v4），没有改变 schema-2 的字段定义，故无需数据库结构迁移；旧快照按原 pipeline 加载，不重新解释、补造位置或改写原下载。Markdown 需要保留 figure / figcaption 或图片定位属性时使用受支持的内嵌 HTML。

[共享规范化](../src/content/revision.py) 统一资源内容身份及路径别名，并携带 CSS 的来源基准和文档作用域；格式解释留在 Reader。[ExportPlan](../src/export/planning.py) 先确定全部输出位置，再由 Writer 重写规范引用，避免各格式分别猜测文件名与目标。具体顺序、导航、样式和损失预期由 TODO 的 UC-06 承接。

## 权威状态与发布边界

[任务运行时](../src/application/jobs.py) 协调 [SQLite](../src/adapters/persistence/sqlite.py) 与 [文件存储](../src/adapters/storage.py)：数据库是任务状态、身份与产物索引的权威来源，文件保存不可变原件、正文修订及输出。存储键与展示名分离，下载按发布索引定位，避免重名资料互相覆盖或按文件名猜路径。进程缓存不是另一套权威状态，Reader / Writer 不提交任务终态；执行与恢复必须核实所有权。

文件系统与 SQLite 没有共同原子事务，因此文件落盘不等于发布完成，可下载性由持久发布记录决定。具体发布、隔离和恢复顺序以任务运行时为准，行为由 UC-03-S6 / S7 承接。manifest 自身不纳入其文件哈希清单，避免自引用哈希。

数据库结构升级与文件迁移分开；代码回退不等于数据回退，不能假定旧代码能读取升级后的数据。原件、原响应、修订和历史导出是长期资料，不套用临时上传 TTL；清理必须考虑保留策略与引用，共享资源仍被引用时不得删除。升级与数据完整性行为由 UC-03 / UC-08 承接，历史副本边界见 [转换依据](evidence.md#真实旧数据副本)。
