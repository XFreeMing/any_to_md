# 任务、发布与数据保留约束

更新日期：2026-10-19。

本文补充 [转换架构](0002-conversion-architecture.md) 的跨数据库 / 文件系统不变量。行为与验证细节由场景代码维护，未完成范围只列在 [TODO](../TODO.md)。

## 权威状态与身份

所有入口共享 [任务运行时](../src/any_to_md/application/jobs.py)、[SQLite 仓储](../src/any_to_md/adapters/persistence/sqlite.py) 和 [文件存储](../src/any_to_md/adapters/storage.py)。数据库保存身份、任务 / 导出状态及产物索引，文件系统保存不可变原件、正文修订、资源和输出。进程内缓存不能成为第二套权威任务状态，Reader / Writer 不自行提交终态。

来源以内容身份定位，展示名不拼接存储路径；修订记录来源与处理版本且不可原地修改；每次导出有独立身份和目录。下载按发布记录的根内相对路径、大小与哈希定位，不能只存 basename 再猜文件位置。共享状态不意味着不同任务可以覆盖同一导出。

任务领取与终态更新须检查执行所有权，恢复须重新核实租约，不能抢占仍活跃的任务。重试建立新的执行记录并保留历史结果。具体状态和字段以 [任务模型](../src/any_to_md/domain/jobs.py) 及仓储实现为准，不在文档另抄 schema。

## 发布不是跨系统原子事务

文件系统与 SQLite 不能一起原子提交，因此先在独立 staging 写产物，核验后发布到独立目录，再提交可下载状态。下载只能引用已提交发布的产物记录；文件已存在不等于可下载。

清单与数据库共用一次采集的产物元数据，manifest 自身校验独立处理，避免自引用哈希。打包保持本地资源与导航关系，不用 ZIP 扁平化消除目录层级。

提交中断后必须能够辨认未完成导出、记录失败并隔离文件；恢复可以补做未完成的隔离。处理异常时先核实持久终态，不能把已经成功提交的产物移走或覆盖。失败终态同样受所有权保护，诊断报告采用原子替换，避免再产生半份报告。

发布中断与旧下载保护的可执行说明见 [UC-03-S6](../tests/E2/UC-03-S6.py)，不同任务并发见 [UC-03-S3](../tests/E2/UC-03-S3.py)。

## 升级、恢复与保留

- schema 升级先取得一致性 SQLite 备份，版本读取、DDL、校验与版本提交处于同一写事务；不支持的 schema 明确拒绝，不能按当前结构误读。
- 结构升级不改写被引用文件。确需改变文件时先保留原版及恢复办法，代码回退与数据回退分别处理，不能假定旧代码能打开升级后的数据库。
- 需要新正文时从保留原件经唯一 Reader 生成新修订并记录旧→新关系；原修订 ID、哈希、文件和历史导出不变。仅剩 Markdown 的情况只能使用共享导入并说明不可恢复的损失，不能借此恢复旧引擎；其实现与验收范围仍由 TODO 决定。
- 原件、用户修订和导出不套用临时上传 TTL。回收依据状态、引用和保留策略，共享资源仍被引用时不能删除，不按目录时间盲删。
- 完整性校验放在实际读取的原件、正文或下载边界；损坏内容不能冒充成功，也不要求有效正文重导出读取无关原件。

真实旧数据升级行为见 [UC-03-S2](../tests/E2/UC-03-S2.py)，既有副本证据及其局限见 [转换依据](evidence.md#真实旧数据副本)。场景文件存在、合成旧库通过或曾经验证过副本，都不证明当前原库已经安全升级。
