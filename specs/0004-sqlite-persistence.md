更新日期：2026-10-15。状态：补充契约；共同运行时与实际旧库升级已实现，逐格式 Reader/Writer 收敛仍按 TODO 执行。

本文服从 [唯一转换架构](0002-conversion-architecture.md)，执行顺序见 [TODO](../TODO.md)。不再另外安排 SQLite、Web 或书库迁移路线。

## 1. 唯一事实来源

所有入口使用一个应用服务、一套 SQLite 仓储和一个文件存储根。SQLite 保存来源/书籍/修订身份、任务状态、导出状态和产物索引；文件系统保存不可变原件、规范内容、资源和输出。

Web 进程内对象可以承载调度或短期缓存，不能成为与数据库并行维护的权威任务状态。Reader/Writer 只返回结果和阶段事件，终态由应用层更新一次。

临时上传、失败暂存和长期保留产物可以有不同保留策略，但它们使用同一个存储/回收实现；不能再分别维护 Web FileManager 和书库 LocalStorage 的规则副本。

## 2. 最小契约

| 对象 | 必需信息 |
|---|---|
| Source | 内容哈希、格式、存储键、原始名称/来源 URL；展示名不用于拼接存储路径 |
| Revision | schema/处理版本、规范正文和资源快照、来源、诊断；不可原地修改 |
| Job | 输入、选项、状态、错误、阶段、关联 revision/export；入口共享 |
| Export | 独立导出 ID、所用修订与配置、发布状态、产物与位置索引 |
| Artifact | 根目录内相对路径、类型、大小、哈希、用途及依赖资源 |

已有书籍/节点身份与导出数据按实际需要延用；不先创建搜索、人工修订、多模型缓存或复杂租约的一整套空表。并发任务至少具备原子领取和状态更新；中断任务必须可识别，不能被当成仍成功运行。更复杂恢复机制以实际并发需求补充。

## 3. 发布与下载

1. 独立 staging 中写入本次产物，统一验证内容覆盖、链接、资源及输出限制。
2. 采集一次产物元数据，供 manifest 与数据库共享；manifest 自身校验独立处理，不能形成自哈希循环。
3. 将文件发布到独立不可变导出目录，再提交可下载状态；下载只能引用已发布产物记录。
4. 文件发布和数据库提交不具备跨系统原子性。任一步失败保留诊断，隔离未完成导出，并能在重启时识别和收尾。

下载按产物记录中的相对路径定位，不能只存 basename 再从输出根目录猜路径。带本地依赖的 MD/HTML 默认提供完整包；同一打包器保持目录结构，不因 ZIP 扁平化造成链接失效。

## 4. schema 升级与已有数据

- 先核对实际数据库、schema、快照及访问入口，不能因旧文档写过迁移就批量重写历史正文。本次规划本身不执行数据升级。
- 数据库结构升级先创建一致性 SQLite 备份。被引用文件不改写，无需为结构升级复制全部历史产物；若确需变更文件，必须先保存其原版及可恢复步骤。无需重新导出的历史文件只读保留。
- 确需规范内容时，优先用原件经唯一 Reader 生成新修订。仅剩 Markdown 的来源通过唯一共享 MD 导入规范化，明确不能恢复已丢失的格式，不把这个导入器变成旧生产管线。
- 新规范快照使用新的 revision ID 和内容哈希，保存旧→新关系；原快照、原 revision ID/哈希、旧导出及其引用保持不变，不能在数据库中把原 ID 改指新正文。不维持旧转换引擎以读取历史数据。
- 不支持的 schema 明确拒绝或迁移；不能为“兼容”长期保留两套存储和转换实现。
- 代码整版回退与数据回退分别处理，不能假设旧代码能直接打开升级后的数据库。

## 5. 保留与验证

原件、用户保留的修订和导出不套用临时上传的一小时 TTL。回收检查任务状态、引用与保留策略，不能仅按目录修改时间删除。共享资源仍被引用时不得删除。

完成验证包括：服务重启任务可查、不同入口共享状态、嵌套产物可下载、多个导出不互相覆盖、发布中断无半成品暴露、迁移后旧数据可访问、导出包离开工作目录仍完整。

上述检查在实现期执行并记录；存在 SQLite 类或 schema 文件不等于持久化收敛已经完成。

## 6. 当前实现与边界

- SQLite schema 4：升级的版本检查、列读取、DDL、外键检查和版本提交置于同一个写事务中。通过单独只读连接创建变更前备份；并发初始化不会使用旧列快照重建已升级的表。
- `application/jobs.py` 是 Web 全格式与 EPUB CLI/批处理的共同运行时。任务在读取前建立，排队/领取是条件更新，执行时续约；重启及周期恢复失败任务并隔离未提交产物。Web 原内存任务/文件管理器已删除。
- 文件先发布，数据库后提交；发布异常会核实持久终态，不能移动或覆盖已提交成功的产物。失败先提交受所有权保护的终态，再隔离文件和写诊断；恢复会补做未完成隔离。JSON 报告使用临时文件原子替换。
- 下载只读取成功导出的产物记录，并验证根目录约束、大小与哈希；重试返回新的任务 ID，历史导出不覆盖。
- 已盘点的 6 个旧快照均有保留原件。新导出使用唯一 Reader 重建，校验旧快照身份/哈希，在成功发布事务内保存 schema 1→2 的 `revision_migrations`；旧快照和导出不原地升级。旧导出可继续通过原存储路径访问；旧产物没有新版下载视图时，需从原件生成新导出，不临时重打包或篡改旧清单。
- 实际数据库未改写，升级及重新导出仅在副本执行；对应证据见阶段归档，当前进度只在 TODO 维护。EPUB/HTML/DOCX 已接入共同 Reader/Writer，URL/PDF/图片转换业务仍待收敛；这项历史数据验证不代表所有格式的效果验收。
