# 规范内容、章节与多视图契约

更新日期：2026-10-15。状态：重规划的补充契约，尚未全部实现。

本文服从 [唯一转换架构](0002-conversion-architecture.md)；进度只在 [TODO](../TODO.md) 记录。旧的阶段安排、两套转换器并存和人工确认节奏已撤销。

## 1. 正文只有一份

规范内容修订保存规范化 XHTML/DOM 内容、章节树、有序来源、资源和诊断。当前工作区 `BookRevision` 已使用 schema 2 的 HTML 片段并移除 `content_markdown`；这是未完成切换中的代码事实，不表示全部入口与历史数据已验收。沿用现有模型即可，不为类型命名另建副本。MD/HTML/PDF 都是派生产物，不同时保存两份可独立修改的正式正文。

章节节点引用有序内容片段，父章引言、子节正文、子节后的补充各有明确归属。一个内容片段只有一个直接归属；分章文件、目录项和章节节点分别建模，不能假设一个源文件就是一章。

原文件和原始响应作为不可变证据保留。导出从已经发布的规范修订读取，不因选择另一种格式重跑 Reader 或 OCR。

## 2. 目录、正文顺序与边界

- EPUB 目录用于导航和层级，spine 用于正文阅读顺序，二者冲突必须诊断。
- 保留父节点、卷/部/章/节、前言、附录和无正文分组。未列入目录的正文也必须覆盖。
- 一文件多章通过真实锚点和内容边界切分；一章多文件按来源顺序合并，物理 `_split_NNN` 不自动升级为章节。
- 重复目录项可以引用同一节点，不能复制一份正文。缺锚点时不使用整篇 HTML 填满每一章。
- 无目录或无可靠章节时保留完整有序正文并报告实际粒度；严格分章请求不能伪称成功。
- DOCX/HTML/PDF 的结构证据由相应唯一 Reader 提供，共享内容归属与覆盖检查；不维护每种输出自己的章节规则。

节点身份独立于标题和文件名；同修订多次导出保留身份。跨来源或重新识别后的身份匹配不能仅靠标题保证，无法可靠匹配时明确产生新节点。

## 3. 内容与资源保留

规范 DOM 保留段落、行内样式、列表、代码、链接、图片候选、表格跨度和脚注关系。中文、空格、换行及代码缩进按各自语义处理，不用全局正则压缩一切空白。

代码清单识别、相邻强调合并、伪标题清理等已有规则要用源文和边界样本验证；保留有效规则而非保留整个旧 Reader。Markdown 转义与表格序列化只在唯一 MD Writer 执行。

资源表以内容哈希去重，并保存来源路径别名。图像、`srcset`、必要 CSS/字体资源由同一解析层处理；CSS 必须保留来源基准和文档作用域，避免多章合并后互相污染。

内部引用在规范内容中解析为节点/锚点引用，实际文件路径由导出计划产生。外部 URL、来源 URL 和本地产物路径分开表达；无法解析的原引用保留诊断，不静默改成错误目标。

## 4. 统一导出计划

一次计划确定正文顺序、切分单元、文件名、节点锚点、资源位置和各格式目标地址。整体与分章 MD 共用同一个 Writer；HTML 的屏幕/打印样式共享结构；PDF 直接使用 HTML Writer 的打印结果。

- 先规划全部位置，再渲染和重写链接；不用扫描已生成文件名反推章节。
- 文件名清洗、UTF-8 长度、保留名称、冲突处理和短 ID 只维护一套规则。
- 目录和位置索引从同一章节树与计划生成；用户未选择交付的视图不能成为导航目标。
- 复杂表格在 MD 中可保留 HTML，HTML/PDF 保留模型中的单元格和跨度；不可表达的信息进入损失报告。
- 导出包移动后，图片、CSS、本地链接和分章导航仍可解析。多文件结果通过统一打包逻辑交付。

## 5. 效果检查

独立基准检查源正文/页面的完整性，内部检查每个正文片段只归属一次，两者缺一不可。生成目录、标题和导航与源正文分开计数，不把正常导航重复当正文重复。

代表性样本覆盖无目录、嵌套目录、缺/重复锚点、跨文件章节、父章引言、中文长标题、图像候选、表格跨度、脚注、代码中的标题符号和样式作用域。MD 做语义/链接检查，HTML/PDF 做实际渲染检查。

当前实现的样本效果和这一目标契约分开记录；没有真实对照时不写“已保真”或“效果最佳”。
