# 正文、身份与导航约束

更新日期：2026-10-19。

本文补充 [转换架构](0002-conversion-architecture.md) 中难以由单一场景表达的共同不变量；格式细节与验收行为以场景代码为准，未实现或未验收的范围见 [TODO](../TODO.md)。

## 一份正文，多种视图

[BookRevision](../src/any_to_md/domain/book.py) 是唯一正式正文：有序 HTML 片段、章节树、来源、资源与诊断共同组成修订。MD/HTML/PDF 都是派生视图，不能与修订分别编辑。原件及原响应是不可变溯源证据，不是另一套正文模型。

每个正文片段只有一个直接归属；父章引言、子节正文和子节后的补充按来源顺序保留。章节节点、导航项、源文件和输出文件不是一一对应关系：导航可以多次指向同一节点，正文不能因此重复。章前内容与空边界必须保留位置，不能因生成标题而被前移或吞并。

来源快照回放允许 Reader 重新解释已捕获字节，但不再读取外部来源；从适用的已发布修订重导出则直接交给 Writer，不重跑 Reader 或 OCR。适用性取决于来源身份、解释选项与 pipeline 版本，输出格式不改变正文身份。这是复用契约，剩余实现由 TODO 的 US-12 / UC-08 管理，不能据本文视为已经实现。

## 导航、顺序与身份分开

- 来源目录提供导航和层级，来源阅读顺序决定正文顺序；EPUB 的 TOC 与 spine 冲突必须诊断，目录未列出的正文仍须覆盖。
- 一文件多章使用真实锚点和边界，一章多文件按来源顺序合并；物理分片名不能自动成为章节。缺锚点时不能用整篇正文填充每一章；无可靠章节时保留完整正文并说明实际粒度。
- 节点身份独立于标题及输出文件名，同一修订多次导出保持身份；变化来源生成新修订，不能只凭同名标题假定跨版本节点相同。
- 来源定位、规范节点/锚点和导出地址分别表达。内部引用先指向规范身份，输出相对路径由 [ExportPlan](../src/any_to_md/export/planning.py) 决定；无法解析的引用保留诊断，不能猜错目标。

内部“每个片段只归属一次”只能证明模型自洽，不能证明 Reader 没有漏读；场景必须另以原件或独立参考验证完整性。生成目录和导航与源正文分开计数，避免把正常导航重复误判为正文重复。

## 资源与视图边界

[共享规范化](../src/any_to_md/content/revision.py) 处理正文、资源和引用，格式 Reader 保留各自来源解释。资源以内容哈希去重，并保留路径别名；CSS 和嵌套资源必须携带来源基准与文档作用域，避免多章合并后互相污染。代码缩进、正文空白和列表等按语义处理，不能用全局清洗规则误改正文。

导出先规划全部位置，再生成内容及重写链接；命名、冲突处理和资源位置只维护一套规则。目录只能指向本次实际交付的视图。复杂表格在 Markdown 中可保留 HTML，无法表达的信息进入损失诊断；不能为格式整齐而丢掉单元格关系。

导出包必须脱离原来源和工作目录仍可阅读，对应 [UC-03-S4](../tests/E2/UC-03-S4.py)。正文复用的 PDF 行为入口为 [UC-01-S5](../tests/E1/UC-01-S5.py)；这些链接不声明通过状态。其余格式语义与资源边界的待验收场景由根 TODO 管理，不在本文重复 Examples。
